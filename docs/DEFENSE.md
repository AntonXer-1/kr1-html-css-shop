## 22 вопроса из задания

### 1. Зачем отдельный репозиторий для контрольной?

Чтобы код, документация и история именно этого проекта были в одном месте,
а преподаватель мог открыть ссылку и проверить результат. Наш репозиторий
kr1-html-css-shop был создан для этого проекта и расширен после практик.

### 2. Чем многостраничный сайт отличается от одностраничного?

У многостраничного сайта разные HTML-документы и URL: catalog.html,
product.html и т. д. Переход загружает новый документ. Лендинг может состоять
из одного HTML с секциями. SPA тоже обычно загружает один документ, но
меняет интерфейс и маршруты через JavaScript. В этой работе не SPA.

### 3. Какие страницы обязательны?

Главная, каталог, карточка товара, заявка и контакты. Все пять в корне проекта.

### 4. Что такое единая навигация?

Одинаковые пункты и ссылки на всех страницах. У нас nav с ul и пятью a.
aria-current="page" отмечает текущую страницу для вспомогательных технологий,
CSS дополнительно подчёркивает её.

### 5. Что такое якорная ссылка?

Ссылка на элемент с id: href="#specifications" ведёт к id="specifications".
catalog.html#mouse-details сначала открывает каталог, затем нужный раздел.
Это переход к месту в документе, а не отдельная страница.

### 6. Какие семантические теги использованы?

header — шапка; nav — навигация; main — основной контент; section — раздел;
article — самостоятельная карточка; aside — дополнительная информация;
footer — подвал. Они объясняют назначение частей, а не задают внешний вид.

### 7. Почему один main?

Он обозначает главный контент страницы. Один видимый main помогает однозначно
найти его, например экранному диктору. Шапка, меню и подвал находятся вне него.

### 8. Зачем article для карточки?

Карточка — самостоятельное описание товара: заголовок, описание, цена
и действие. Её смысл сохраняется отдельно от списка остальных товаров.

### 9. Как устроена таблица?

table — таблица; caption — её название; thead — заголовок; tbody — данные;
tr — строка; th — заголовочная ячейка; td — обычная. scope="col" связывает
заголовок со столбцом, scope="row" — со строкой.
Пример: product.html, раздел «Характеристики».

### 10. Какие элементы формы реализованы?

input для имени (text), email, телефона (tel), даты (date), согласия (checkbox).
select — товар и тема; textarea — комментарий; button type=submit — проверка.
label связан с полем через for/id. name — имя поля в потенциальной отправке.

required запрещает пустое значение, minlength задаёт минимум длины,
type=email проверяет формат адреса, pattern — формат телефона.
type=tel сам по себе не проверяет телефон. placeholder — подсказка, не label.

novalidate отключает автоматическую проверку при submit, но мы вызываем
checkValidity и reportValidity из JS. preventDefault останавливает отправку.
aria-invalid="true" сообщает об ошибке; CSS выделяет её.

### 11. Чем CSS-модальное окно отличается от dialog?

CSS-вариант можно показать через :target, но нужно отдельно продумывать
фокус и блокировку фона. dialog.showModal() открывает нативное модальное окно
в top layer: фон становится недоступен, фокус находится внутри, Escape
закрывает окно. ::backdrop оформляет затемнение. У нас используется dialog.

### 12. Зачем CSS-переменные?

Хранят общие значения. В :root есть --color-primary, а кнопки и ссылки
используют var(--color-primary). Меняем один токен — меняется весь акцент.
Это помогает поддерживать единый стиль.

### 13. Чем :hover отличается от :focus-visible?

hover — указатель над элементом; focus-visible — видимый клавиатурный
фокус по решению браузера, например после Tab. Пользователь должен понимать,
какой элемент активен без мыши. У нас focus-visible даёт outline.

### 14. Где и зачем Flexbox?

В меню и строке действий карточки. Flex удобен для размещения
элементов в одном направлении: display:flex, gap, align-items,
justify-content, flex-wrap.

### 15. Где и зачем Grid?

В product-grid — сетке карточек. Grid управляет колонками и строками.
repeat(3, minmax(0, 1fr)) создаёт три равные колонки, а gap — промежуток.

### 16. Что такое БЭМ?

Соглашение об именовании: Блок, Элемент, Модификатор.
product-card — блок, product-card__title — его элемент,
button--secondary — модификатор. БЭМ не библиотека и не особый синтаксис CSS.

### 17. Чем блок отличается от элемента?

Блок — самостоятельная часть интерфейса. Элемент имеет смысл внутри блока.
product-card можно переносить, его title — часть именно этой карточки.

### 18. Чем элемент отличается от модификатора?

Элемент — составная часть: __title. Модификатор — вариант: --secondary.
У кнопки классы button и button--secondary, базовый класс остаётся.

### 19. Почему не оформлять всё через id?

id уникален и удобен для якорей, label и поиска в JS. У #id высокая
специфичность, такие стили сложно переиспользовать и переопределять.
Классы можно назначать многим карточкам и компонентам.

### 20. Что должно быть в README?

Название, описание, автор и группа, технологии, структура, запуск,
страницы, ссылка на Pages, собственные улучшения. Мы также добавили карту
требований, команды тестов и ссылку на эту памятку.

### 21. Что добавлено самостоятельно?

К практикам добавлены пять связанных страниц, сетка карточек на Grid,
таблица характеристик, БЭМ-классы и фиксированная ссылка наверх.

### 22. Чем дополнения полезны?

Меню позволяет перейти между страницами, сетка размещает карточки в ряд,
таблица упорядочивает параметры товара. БЭМ делает имена классов понятнее,
а fixed-ссылка остаётся доступной при прокрутке.

## Дополнительные понятия из практик

head — служебная информация документа; header — видимая шапка страницы.

Четыре meta: charset — кодировка UTF-8; viewport — масштаб на устройствах;
description — описание страницы; author — автор.
title — название вкладки, это отдельный тег, не meta.

Box model: content — содержимое, padding — внутренний отступ,
border — рамка, margin — внешний отступ.
При content-box width задаёт только ширину содержимого.
При border-box width включает содержимое, padding и border, но не margin.
У нас * { box-sizing: border-box; }.

relative — остаётся в потоке и задаёт ориентир абсолютным потомкам.
absolute — вне обычного потока; у нас бейдж внутри карточки.
sticky — приклеивается при прокрутке, но в нашем сайте не используется.
fixed — привязан к окну; у нас ссылка наверх.
z-index задаёт порядок внутри контекстов наложения; dialog в top layer,
его не нужно «перебивать» огромным z-index.

hidden input не рисуется, но хранит выбранный товар. Это не секрет и не защита.
data-product — дополнительное значение на кнопке; JS читает button.dataset.product.
defer — выполнить скрипт после разбора HTML.

git add подготавливает изменения; git commit создаёт снимок;
git push отправляет коммиты на GitHub. Git — система контроля версий,
GitHub — сервис размещения репозиториев. README.md — Markdown-документ.
