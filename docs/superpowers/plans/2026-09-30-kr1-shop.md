> Implement inline using executing-plans.

**Goal:** Deliver the existing repository as a five-page educational HTML/CSS shop.
**Spec:** docs/superpowers/specs/2026-09-30-kr1-shop.md
**Architecture:** static HTML pages, one CSS file, local SVG assets, optional dialog/form controller.
**Stack:** HTML5/CSS3, minimal vanilla JS, Python unittest, Node test, Playwright.

## Global constraints

Preserve previous validation examples. No backend, frameworks, analytics, payments
or false claim of submission. Work on feature/kr1-multipage-shop, not main.
User has confirmed implementation and requested automatic confirmation of further
in-scope changes. No LMS submission. README gets a dedicated commit.

**Files:** index.html, catalog.html, product.html, order.html, contacts.html,
css/style.css, js/main.js, images/*.svg, tests/test_site.py,
tests/test_multipage.py, tests/multipage.test.mjs.

**Interfaces:** Produces five static routes and existing form IDs; consumes
the existing dialog and validation behavior.

1. Run existing Python and Node tests. Expected: all 14 pass.
2. Add structural tests for five pages, unified links, local resources,
accessible table and form labels, product detail links. Add Chromium tests for
route navigation, standalone order validation, no data transmission, layout.
Expected: new tests fail because new pages do not exist.
3. Implement semantic pages, meaningful products and SVGs, shared BEM CSS,
guard optional JS elements. Update old sample product expectations to actual names.
4. Run the whole suite, inspect screenshots of all five pages. Expected:
all tests pass; no clipped text or horizontal overflow, dialog stays usable.
5. Commit code and tests. Expected: commit on the feature branch.

### Task 2: Document and publish proof

**Files:** README.md, docs/DEFENSE.md.
**Interfaces:** Consumes implemented routes/selectors and deployment links.

1. Write requirement map and defense answers based on actual code. No prose tests.
2. Run entire suite and diff whitespace check. Expected: all pass.
3. Commit documentation separately. Expected: README appears in its own commit.

## Review focus

Check unsupported dialog behavior, Escape/reopening form errors, stale selected
product after reset, links leading to the wrong product, accessibility of table,
honesty of demo contacts/form, mobile overflow and labels. Tests cannot establish
visual quality or verify each sentence of defense prose.
